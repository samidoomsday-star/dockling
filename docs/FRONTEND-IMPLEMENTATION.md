## Preview behavior

Use a named synthetic workspace with an unmistakable preview banner. No real upload, provider request, key storage, login, payment or document conversion. Stateful UI interactions use an in-memory demo adapter with fixture-backed results and reset on reload. Financial values are exact strings. The adapter must not describe its results as real extraction/reconciliation. Explicit sample exports are generated by the existing Python writers and bundled separately; they are not exports of user-uploaded files. Operations requiring server support show the dependency clearly rather than returning fake success.

Real API mode has a typed same-origin contract and explicit unsupported/unavailable responses. Demo mode cannot silently substitute for API failures. Authentication, authorization, Decimal validation, reconciliation, revision/history and private storage must remain server-authoritative in the integration stage.
