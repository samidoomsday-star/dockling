## Implementation sequence

1. **Prepared:** receiving-assistant instructions, private evidence ledger, owner decisions, release checkpoints and conservative customer offer.
2. **Prepared:** invitation → onboarding → conversion/source review → import → manual billing → support → retention/exit operating procedure using the existing account, entitlement and operations features.
3. **Prepared:** incident/stop conditions, coordinated rollback requirements, feedback handling and broader-release decision.
4. **Pending:** resolve native critical/high findings and complete independent security/dependency/model review.
5. **Pending:** select and authorize actual hosting, region, business/payment eligibility, budget, domain, retention, backup and support promises. Provision only after those prerequisites; verify selected-host TLS, isolation, monitoring, recovery and measured capacity.
6. **Pending:** permitted field samples, actual destination imports, first-time-user accessibility review and complete allocated costs. Use the existing private field validator; do not infer these from fictional test data.
7. **Pending:** owner review of a concrete deployment/offer, followed by explicit approval for publication and invitations.
8. **Pending:** observe an actual paying cohort through a complete statement/billing/retention cycle, implement findings, rerun affected checks and seek the broader-release decision.

## Completion evidence

Preparation is complete when another assistant can find the instructions and identify outstanding prerequisites without inventing credentials, terms or outcomes. The full phase is complete only after the actual approved pilot cycle, verified customer outcomes and follow-up changes. A documentation update, green CI workflow, manually marked ledger or loopback rehearsal cannot complete the external phase.
