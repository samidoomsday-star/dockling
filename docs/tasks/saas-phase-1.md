## What the owner will get

A real local server that recognizes signed-in test users, keeps two customers' workspaces separate, stores job metadata across restarts, and checks permission on every request. A beginner setup guide will start the local web services. Genuine document upload/conversion is Phase 2; review/export is Phase 3. The current frontend demo remains usable while real-mode integration develops.

## Acceptance fixture and failure cases

Use synthetic users with opaque issuer subjects, A/B workspaces, approved membership, and opaque UUID jobs. No real email/key or customer document is needed. The owner of A cannot reach B by altering URL/body/cursor; A's viewer cannot create/edit/remove/consent/buy; a platform admin without a scoped grant cannot read A's rows or artifacts. Invalid member changes cannot create a workspace with no active owner. Worker/service identities do not inherit unscoped customer reads.

Run integration tests against PostgreSQL rather than SQLite pretending to validate production SQL/locking. Exercise database/object-store unavailability, restart and concurrent command replay. New route/body version changes must update OpenAPI examples and the feature matrix together. Test expectations for later-phase routes remain pending, never reported as passed for this foundation.

## Pending choices that do not block this build

US/Europe are likely target markets, but first country, data region, business country, budget, retention/support and payment vendor remain unresolved. Use isolated synthetic local services; no paid resource, public deployment or actual payment/provider inference is necessary. Freeze production provider/config choices only after those answers and the capacity assessment. Hosting and real-data gates remain in the overall roadmap.
