# Implementer threat review and external-review handoff

This records the implementer's analysis of the actual Phase 6 boundaries. It is **not an independent audit**. Read [the operating guide](PHASE6-OPERATIONS.md) and [open native findings](PHASE6-SECURITY-FINDINGS.json) before interpreting functional test results.

| Boundary / concrete threat | Implemented protection and observed evidence | Remaining release check |
| --- | --- | --- |
| Browser → API: stolen/expired authority, CSRF, old private cache | Maintained OIDC/PKCE, opaque HttpOnly sessions, server expiry/revocation, origin/CSRF writes, server roles and exact workspace scope. Browser real logout and denied-write tests verify private cache disappearance. | Production HTTPS cookie/identity configuration, key/session rotation and recovery flows; independent auth review. |
| Customer A → Customer B: guessed IDs, wrong-parent source/downloads, shared worker | Scoped queries and foreign keys, authorized artifact streams, generation/revision/actor/deletion publication fences. Real two-workspace negative tests include documents, connections, invoices and restored tombstones. | Independent tenant review and selected deployment's service-role/network boundaries. |
| Public uploads → parser: oversized/malicious documents and resource exhaustion | Size/page/pixel/type/password limits, bounded API bodies/deadlines/admission, isolated non-root read-only CPU worker with no public egress, generation-safe publication. Original and SaaS abuse tests stay enabled. | Unfixed native high/critical findings; patch/rebuild and independent parser/container review. Host-specific sustained load and saturation alerts. |
| Administrator → private document: implied support authority or stale MFA | No implicit customer membership; named expiring revision/data-class support grants; fresh MFA on reads, revocation and audit. Anonymous operating reports contain fixed counts/alerts. | Manual least-privilege review of production identity roles and break-glass/support policy. |
| BYOK/model → external provider: SSRF, oversharing, unexpected charges | Workspace-bound encrypted vault, validated HTTPS/public addresses/redirect rules, metadata bounded separately from inference, exact consent/terms/model/effort binding, minimized payloads and persistent conservative reservations. Fake provider tests exercise supported Max and uncertain results. | Actual selected-provider terms/data region, authorized integration tests and verified interrupted-process teardown. Page/request limits are not a currency spending cap. |
| Restored backup → authority/deletion resurrection or duplicate paid work | Independent authenticated encryption, bounded manual archive extraction, scoped immutable evidence, sessions/invitations/consent quarantine, cancelled work, uncertain attempts/reservations held. Current deletion journal replay removes exact restored job objects with no inherited certificate. | Independently retained current deletion/membership/payment journal, identity/vault key custody and selected-host complete restore/teardown rehearsal before any intake resumes. |
| Migration → lost immutable invoice evidence | Forward-only guarded migrations; disposable matched 0011 restore/0012 upgrade rehearsal preserves fictional exact USD 25.00 paid invoice and evidence. | Host-specific release/rollback procedures with matched snapshot, newer external-ledger reconciliation and documented recovery objectives. |
| Payment/support message → false commercial action | Manual immutable versioned evidence; unique references, strict exact amounts and tested legal states. Checkout/email disabled; privacy/support messages grant no implicit export/removal. | Merchant eligibility, approved prices/taxes/policies and sandbox webhooks if a real checkout integration is enabled. Manual evidence cannot verify the external payment itself. |
| Build/dependency/model → supply-chain compromise or license conflict | Hash-pinned Python artifacts, npm lock, official digest-pinned image, signed apt updates, verified scanner archive, pinned model hashes and explicit license inventory. | Complete transitive/native/model-weight notices and commercial terms; independent review of CI/host secrets and all production service images. |

The source/model data flow and existing permission contracts remain in `docs/saas/` and `contracts/saas/`. File unlink and a database terminal state do not prove memory/SSD erasure. Live removal certificates exclude backup/provider/browser/downloaded copies. Logs, private archives and identity traces must remain private; a support screenshot must never reveal a statement or secret.

Before launch, an independent reviewer needs the final source/image commits, selected HTTPS identity/API/storage/worker topology, service-role policies, provider/deletion/backup diagrams, sanitized test and scan evidence, and the concrete proposed customer limits. Provide a synthetic review environment and explicitly scoped access; do not send production secrets or statements. Record every finding with owner, severity and retest evidence. All open critical/high findings block launch; the implementer cannot award an independent approval to their own work.
